1. Escopo (mínimo necessário para atender ao PDF) => Na reunião de ontem (14/05), 
validamos o escopo do Chatbot, conforme abaixo: 
O chatbot deve: 
1. Responder dúvidas frequentes (FAQ) de segurado de auto. 
2. Apresentar cotação simulada (mock) de seguro auto, a partir de dados coletados 
na conversa. 
3. Direcionar solicitações fora do escopo para atendimento humano (fallback). 
O que NÃO está no escopo (não fazer): 
• Integração real com API de seguradora ou cotador de mercado. 
• Integração com CRM (opcional do PDF - descartado pelo prazo). 
• Histórico anonimizado de tickets (opcional do PDF - descartado). 
• Multi-ramo (a princípio, apenas auto neste MVP – caso sobre tempo, podemos 
criar cotação de outros ramos). 
• Autenticação, persistência de usuário, banco transacional. 
 
2. Arquitetura mínima 
Fluxo lógico (mesmo nas duas opções): 
Usuário 
   │ 
   ▼ 
[ Chat UI ] 
   │ 
   ▼ 
[ Orquestrador / Router de intent ] 
   ├── intent = FAQ / dúvida         → [ RAG: vector store + embeddings ] → [ LLM ] → resposta 
   ├── intent = cotação              → [ Fluxo de coleta de dados ]       → [ Mock de cotação ] → resposta 
   └── intent = humano / fora escopo → mensagem de encaminhamento
